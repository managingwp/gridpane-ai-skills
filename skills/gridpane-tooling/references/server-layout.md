# Server layout for tooling

Where GridPane puts its own scripts, the state and config a tool reads, and the
logs it writes — from the developer's point of view. For the operational path map
(webroots, per-site logs, vhosts) see `gridpane-core/references/paths.md`; this
file focuses on the tooling layer and adds the developer-facing locations.

All paths assume root (or sudo) over SSH. `{site.url}` is a site's primary
domain.

## GridPane's deployed tooling

| Path | What it is |
|---|---|
| `/usr/local/bin/gp` | The `gp` dispatcher. Sources every `lib/*.sh`, then dispatches on `$1`. |
| `/usr/local/bin/gp<cmd>` | Wrapper scripts that inject a subcommand and re-enter `gp` (`gpsite`, `gpmonit`, `gpbup2`, `gpfix`, `gpworker`, …). |
| `/usr/local/bin/lib/*.sh` | The implementation, one module per area, sourced by `gp`. |
| `/usr/local/bin/monit-scripts/` | Per-service monit check scripts (versions, config syntax, resources). |
| `/usr/local/bin/gridpane.ver` | The deployed scripts version marker; the update system compares against it. |
| `/usr/local/bin/wp` | Bundled WP-CLI (PHP). |
| `/usr/local/bin/monit`, `/usr/local/bin/duplicacy` | Bundled binaries. |
| `/etc/monit/conf.d/` | Monit service and program definitions (`programs`, `mysql`, `nginx`/`openlitespeed`, `redis`, `fail2ban`, `filesystem`, `system`). |
| `/etc/monit/monitrc.d/` | Additional monit config (e.g. `fail2ban`). |

The wrapper pattern is small and worth copying when you add a shim:

```bash
#!/bin/bash
# Copyright GridPane
set -- "monit" "$@"
. /usr/local/bin/gp
```

(`gpsite` guards with `[[ $1 != "site" ]] && set -- "site" "$@"` so an explicit
subcommand is not doubled.)

## GridPane state and credentials

| Path | Holds |
|---|---|
| `/root/gridenv/*.env` | Server-level state (see `gridpane-core/references/gridenv.md`). |
| `/var/www/{site.url}/logs/{site.url}.env` | Per-site state, including `cache-type` (see `gridpane-core/references/site-env.md`). |
| `/opt/gridpane/` | Runtime state, tokens and logs (`backup.log`, `active-site-audit.log`, `acme.monitoring.log`, `backups.monitoring.log`, …). |
| `/opt/gridpane/backups/` | Local backup tree (`configs/`, `databases/`, `duplications/`, snapshots). |
| `/root/gridcreds/` | Credentials (`gridpane.uuid`, `wp.user`, `wp.pw`, `wp.email`, `honeypot.creds`). **Secrets.** |
| `/root/.acme.sh/` | ACME (Let's Encrypt) account and cert state. **Secrets.** |
| `/run/gridpane/` | Runtime locks (tmpfs; e.g. `gpupdate` holds its single-instance lock here). |

Never print or commit the contents of `/root/gridcreds/`, `/root/.acme.sh/` or
the secret keys in `/root/gridenv` and per-site `.env` files.

## Logs

| Path | Answers |
|---|---|
| `/var/log/gridpane.log` | GridPane/`gp` actions (what ran, when). |
| `/var/log/health-check.log` | Server health-check results. |
| `/opt/gridpane/*.log` | Backup, ACME/certbot, audit and clone monitoring. |
| `/var/www/{site.url}/logs/` | Per-site logs (debug, staging, SSL, WAF, cron, …). |
| `/var/log/monit.log` | Monit checks and service restarts. |
| `/var/log/nginx/{site.url}.access.log`, `.error.log` | Nginx per-site traffic and errors. |
| `/var/log/ols/{site.url}.*` | OpenLiteSpeed per-site logs. |
| `/var/log/mysql/error.log`, `/var/log/mysql/slow.log` | Database errors and slow queries. |
| `/var/log/php/{version}/fpm.log`, `/var/log/{site.url}{ver}.log.slow` | PHP-FPM service and slow logs. |
| `/var/log/fail2ban.log`, `/var/log/auth.log` | Brute-force and authentication events. |
| `/var/log/ufw_log`, `/var/log/syslog` | Firewall and system. |

Tools that log should follow the same conventions: append to
`/var/log/gridpane.log` for GridPane-level actions and use syslog (`logger`) for
service events.

## Config a tool may read

| Path | Holds |
|---|---|
| `/etc/nginx/nginx.conf`, `/etc/nginx/conf.d/`, `/etc/nginx/common/`, `/etc/nginx/sites-available/` | Nginx stack and per-site config. |
| `/etc/nginx/extra.d/`, `/var/www/{site.url}/nginx/` | Safe include locations (see `gridpane-core/references/paths.md`). |
| `/etc/php/{version}/fpm/pool.d/{site.url}.conf` | Per-site PHP-FPM pool (managed). |
| `/etc/php/{version}/…` | PHP config per version. |
| `/etc/redis/redis.conf`, `/etc/redis/redis-page.conf`, `/etc/redis/redis-object.conf` | Redis service config. |
| `/etc/mysql/` | MySQL/MariaDB config. |
| `/etc/fail2ban/` | Jails and filters. |

## Schedules and services

| Path | Holds |
|---|---|
| `/etc/cron.d/gp-cron-*`, `gp-daily-scan-*`, `gp-wpmanager-*`, `backup-*` | GridPane cron jobs. |
| `/etc/logrotate.d/gp*`, `debug-log-*`, `fortress-logs-*` | Log rotation. |
| `/etc/systemd/system/` | GridPane unit files. |

## Paths an update overwrites — do not hand-edit

`gpupdate` replaces the deployed scripts, so anything under `/usr/local/bin`
(including `lib/`) is temporary. Monit configs under `/etc/monit` are also
regenerated by `gpmonit`/`gp server -update-monit`. Put custom tooling outside
these trees, or re-deploy it after updates; see
`references/developing-tools.md`.
