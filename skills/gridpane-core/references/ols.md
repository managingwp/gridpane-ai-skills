# OpenLiteSpeed (OLS) on GridPane

The OLS stack is a per-server alternative to Nginx. Confirm which one a server
runs before using any path or command here: `grep '^webserver:' /root/gridenv/promethean.env`
(`nginx` or `openlitespeed`), or `gpols --help` / `systemctl status lshttpd`.

For the shared path map see `paths.md`; this file is the OLS-specific model.

## Configuration tree

| Path | What it is |
|---|---|
| `/usr/local/lsws/conf/httpd_config.conf` | Main server config. |
| `/usr/local/lsws/conf/vhosts/{site.url}/vhconf.conf` | Per-site virtual-host config (generated by `gpols`). |
| `/usr/local/lsws/conf/mime.properties` | MIME map. |
| `/usr/local/lsws/conf/backup/` | Config backups. |
| `/usr/local/lsws/conf/cert/_default/` | Default self-signed cert. |
| `/usr/local/lsws/conf/.htpasswd` | Basic-auth file. |
| `/var/www/{site.url}/ols/rewrites.conf` | Site rewrite rules (the KB recommends this over `.htaccess`). |

OLS supports `.htaccess` and GridPane watches it for changes, but add custom
rewrite rules to `rewrites.conf`; after editing it run `gpols site {site.url}`.

## Services and commands

- `gpols` is a wrapper for `gp ols` (`gpols <cmd>` → `set -- "ols" "$@"`).
- `ols` is a wrapper for `/usr/local/lsws/bin/lswsctrl`.
- Service: `lshttpd`; Monit watches `/tmp/lshttpd/lshttpd.pid` and port 80
  (`etc/monit/conf.d/openlitespeed`).

`gpols` subcommands (`lib/ols/source/help.sh`):

| Command | Purpose |
|---|---|
| `gpols site {site.url}` | Regenerate a site's vhconf + server config and restart. |
| `gpols httpd` | Regenerate only the main config and restart. |
| `gpols test` / `-t` | Run `/usr/local/lsws/bin/openlitespeed -t`. |
| `gpols log {site.url\|httpd} [-a] [-f]` | Tail a site or server log (error by default). |
| `gpols init` | Create the config/log directories and default cert. |
| `gpols addon` / `redirect` / `site` / `stats` / `pma` | Generate vhconf for add-on domains, redirects, sites, Monit, phpMyAdmin. |
| `gpols env` | Set OLS `.env` values (`ols-log-*`, `ols-memory-*`, `ols-fswatch-latency`). |
| `gpols get` | Read a value from a site's vhconf/`.env` (php, route, cert, cache, …). |
| `gpols version` | Upgrade/downgrade OLS. |

Common flags: `--ssl`, `--wildcard`, `--route none|root|www`, `--php=8.x`,
`--cache redis|redis-off|page|page-off|page-only|php|off`, `--opcache`,
`--multisite=sub-directory|sub-domain`, `--auth`, `--no-restart`, `--quiet`.

Restart alternatives: `systemctl restart lsws`, or
`/usr/local/lsws/bin/lswsctrl restart` (hard restart). Prefer `gpols site`/`gpols
httpd`, which regenerate config first.

## Logs

| Log | Path |
|---|---|
| OLS server access/error | `/usr/local/lsws/logs/access.log`, `/usr/local/lsws/logs/error.log` (symlinked to `/var/log/ols/ols.access.log`, `/var/log/ols/ols.error.log`). |
| OLS stderr | `/usr/local/lsws/logs/stderr.log`. |
| Per-site access/error | `/var/www/{site.url}/logs/{site.url}.access.log`, `{site.url}.error.log`. |
| ModSecurity audit | `/var/log/modsec_audit.log`; per site `/var/www/{site.url}/modsec/modsec_audit.log`. |

`gpols log {site.url}` prints the last 500 error lines; `-a` = access, `-f` =
follow. `gpols log httpd` reads the server log.

## PHP (LSAPI)

OLS runs PHP via LSAPI, not PHP-FPM. Modes are ProcessGroup, Daemon and Worker;
GridPane uses **ProcessGroup** by default and does not offer Daemon (it blocks
per-user `php.ini`). Worker is the on-demand equivalent.

## Caching (LSCache)

- Page caching is the **LiteSpeed Cache** plugin (LSCache), pre-installed on OLS
  sites. It is not a GridPane plugin.
- The GridPane customizer toggles **LSCache Page Caching** and **LSCache Redis
  Object Caching**; the settings are reflected inside the plugin. The reverse is
  not true: changing the plugin does not change the GridPane toggles.
- Redis object cache connects over `/var/run/redis/redis-object.sock` (port `0`,
  DB `0`).
- Cache headers are `HIT`/`MISS` (LSCache), not the Nginx `X-Grid-*` headers.
- OLS shares **one cache directory across all sites**; an aggressive crawler on
  a large site can affect every site (and cause 503s). The KB advises against the
  crawler on a 1-CPU server above 25% hourly CPU.
- Per-site `cache-type` values on OLS: `redis-page`, `page-only`, `redis-only`,
  `off` (see `site-env.md`).

## Security

- No 6G on OLS; use 7G (the OLS variant in `lib/ols/7g/`) and ModSecurity, which
  is CRS-based (`lib/ols/source/modsec.sh`).
- ModSecurity lives at `/usr/local/lsws/modsec` (installed from
  `/opt/gridpane/modsec`, CRS 3.3.0), with per-site
  `/var/www/{site.url}/modsec/{site.url}-main.conf`.
- Fail2ban and the WP Fail2ban integration use the same commands as Nginx.
- IP allow/deny: `/usr/local/lsws/conf/ip_deny.conf`, then `gpols httpd`.

## Gotchas

- **Confirm the stack first.** OLS and Nginx paths and restart commands differ.
- **Regenerate, don't hand-edit.** `vhconf.conf` and `httpd_config.conf` are
  generated; use `gpols`.
- **`.htaccess` changes are watched, `rewrites.conf` changes are not.** Run
  `gpols site {site.url}` after editing `rewrites.conf`.
- **Cache headers differ.** LSCache uses `HIT`/`MISS`; the Nginx `X-Grid-*`
  headers do not apply.
- **Shared cache directory.** One site's crawler can starve the others.
